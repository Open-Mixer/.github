# Language packs

An owner of codes ships the sentences of its codes per language as packs, built from its own spec and `debian/`,
from the same source commit (Open-Mixer/omx-contract#21, Open-Mixer/.github#37).

| | rpm | deb |
|---|---|---|
| owner's pack | `<name>-langpack-<lang>`, noarch | `<name>-l10n-<lang>`, Architecture all, Section localization |
| owns | `/usr/share/<owner>/catalogs/<lang>.json` | the same file |
| ties to the base | `Requires: <base> = %{version}-%{release}`, `Supplements: (<base> and langpacks-<lang>)` | `Depends: <base> (= ${source:Version})` |
| meta pack | `openmixer-langpack-<lang>` requires every owner's pack | `openmixer-l10n-<lang>` depends on every owner's pack |

The languages are omx-contract's list, `/usr/share/omx-contract/languages.json` (`"languages"`), shipped by
omx-contract-data from 3.16.0. The source is the owner's `catalogs/<lang>.json`, one file per listed language and
none for English (the English sentence is the vocabulary's `text.en`).

## An owner adopts it

1. Put the two marker lines where the packs go, in the spec (after the base `%files`) and in `debian/control`
   (after the last stanza):

   ```
   # BEGIN langpacks: generated by langpacks.py, do not edit
   # END langpacks
   ```

2. Write the packs, with `langpacks.py` from a checkout of Open-Mixer/.github:

   ```
   python3 <.github>/.github/actions/langpacks/langpacks.py rpm --spec packaging/<name>.spec --name <name> \
       --base <base> --owner <owner> --catalogs catalogs --languages /usr/share/omx-contract/languages.json
   python3 <.github>/.github/actions/langpacks/langpacks.py deb --debian debian --name <name> \
       --base <base> --owner <owner> --catalogs catalogs --languages /usr/share/omx-contract/languages.json \
       [--moved ca:<first version with packs>]
   ```

   The deb run also writes each pack's `.install` and `.lintian-overrides`. `--moved` marks a language whose catalog
   the base package carried before: its pack Breaks and Replaces `<base> (<< <version>~)`.

3. Take the catalogs out of the base package (`%files` keeps `%dir %{_datadir}/<owner>/catalogs`; the base's
   `.install` names no catalog).

4. Hold them in CI, after omx-contract 3.16.0 or later is installed:

   ```yaml
   - uses: Open-Mixer/.github/.github/actions/langpacks@openmixer-v1
     with:
       name: <name>
       base: <base>
       owner: <owner>
       spec: packaging/<name>.spec
   ```

   It is red when a generated block is stale, when a listed language has no catalog or a catalog names a language the
   list does not, and when `omx-contract translate --check` refuses a catalog (a missing key, a stale entry). The gate
   runs `omx-contract translate --check --owner .`; an owner whose items name another package's (plugin-hostd-protocol
   names omx-clap-core's reply codes) passes `gate:` a command that reads them from a contract directory, such as a
   make target staging its own the way its `check-contract-dir` does.

## The meta packs

`packaging/openmixer-langpacks/build.sh rpm|deb <languages.json> <output dir>` writes the meta packs for the owners in
`packaging/openmixer-langpacks/owners.txt` and the listed languages, then builds them. An owner whose pack the channel
does not serve leaves the meta pack uninstallable, so the channel installability check is red until it ships.

`tests/langpacks.sh rpm|deb` proves all of it on fc44, fc45, bookworm and trixie with an owner fixture.
